# AI Handoff — ЭТП (электронная торговая площадка с ИИ)

Этот файл — контекст для продолжения работы в новой сессии/проекте («ETP X» в интерфейсе Claude). Прочитай его целиком перед тем, как что-то менять в коде.

## Что это за проект

Полноценная ЭТП с ИИ-помощником — не то же самое, что соседний проект `specification` (там простой статичный `index.html` со страницей спецификации Заказчик/Участник). Этот проект (`/Users/emilakmaev/Downloads/etp`) построен с нуля по `PROJECT_BRIEF.md` и `schema.prisma`, которые пользователь уже спроектировал сам до начала работы.

Пользователь **не разработчик** — для любых шагов, которые требуют от него что-то сделать руками (кликнуть в чужой панели, найти ключ, вставить пароль), давай короткие пронумерованные шаги простым языком, без жаргона без пояснения.

## Стек

Next.js 16 (App Router) + TypeScript + Tailwind v4 + shadcn/ui (new-york, база — **Base UI**, не Radix) + Prisma 6.19.3 + Postgres (Supabase) + Supabase Auth + pnpm. Хостинг предполагается Vercel (не GitHub Pages — там не будет работать серверная часть). AI-фичи (Anthropic API) пока не подключены.

## Важные технические решения (не переспрашивать, если не сказано иное)

- **Prisma зафиксирован на 6.19.3**, не 7.x — Prisma 7 убрал `url = env("DATABASE_URL")` из schema.prisma в пользу `prisma.config.ts` + driver adapters, это сломало бы готовую схему пользователя.
- Next.js 16: файл `middleware.ts` переименован в **`proxy.ts`**, экспортируемая функция должна называться `proxy`, не `middleware`.
- shadcn `Button` в этой установке использует `render` проп от Base UI (не `asChild` от Radix): `<Button render={<Link href="/x" />}>text</Button>`. Если `render` рендерит НЕ `<button>` (например, `<Link>`), обязательно добавляй `nativeButton={false}`, иначе консольный warning.
- Дашборд живёт на `/dashboard`, не на `/` — потому что `(marketing)` и `(platform)` route-группы не могут обе резолвиться в корень.
- `Prisma.User.id` = id пользователя Supabase Auth (без отдельной таблицы-связки) — так RLS-политики смогут опираться на `auth.uid()` напрямую.
- Дропдауны (`DropdownMenuLabel` и другие части) обязательно должны быть внутри `<DropdownMenuGroup>` — иначе краш "Base UI: MenuGroupContext is missing". Уже словили и пофиксили один раз в `nav-user.tsx`.
- Шрифт: чинили серьёзный баг — весь текст (включая латиницу) рендерился serif-шрифтом. Причина — циклическая ссылка `--font-sans: var(--font-sans)` в `globals.css` (должно быть `var(--font-inter)`) + отсутствующий cyrillic-сабсет у шрифта. Если в новом shadcn/create-next-app скэффолде снова увидишь нечитаемый/неправильный шрифт — проверяй именно этот паттерн.
- `ref_N` из `read_page`/`find` в браузерном тестировании этого приложения быстро протухают (особенно вокруг дропдаунов/после навигации) — надёжнее кликать через `javascript_tool` (`document.querySelector(...).click()`), чем по устаревшему `ref` или координатам.

## Окружение

На этой машине изначально не было Node/pnpm/brew/nvm в PATH инструмента Bash. Node 24 LTS установлен вручную в `~/.local/node` (тарбол с nodejs.org, без sudo), pnpm активирован через corepack. **Перед любой командой с node/pnpm/prisma** нужно:
```bash
export PATH="$HOME/.local/node/bin:$PATH"
```
Это не сохраняется между отдельными вызовами Bash.

## Supabase — реальный проект подключён

`.env` (в .gitignore, не в репозитории) содержит реальные `DATABASE_URL` (пулер, порт 6543, `pgbouncer=true`), `DIRECT_URL` (сессионный пулер, порт 5432 — нужен для миграций, pgbouncer transaction-mode их не умеет), `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (новый формат `sb_publishable_...`), `SUPABASE_SERVICE_ROLE_KEY` (`sb_secret_...`). `prisma/schema.prisma` datasource содержит и `url`, и `directUrl`.

**"Confirm email" сейчас отключён** в настройках Supabase Auth (тестовые аккаунты сразу получают сессию) — обязательно включить обратно перед реальным запуском.

В базе остались тестовые пользователи/компании от проверки флоу — можно игнорировать или почистить.
