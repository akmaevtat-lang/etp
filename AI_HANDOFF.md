# AI Handoff — ЭТП (электронная торговая площадка с ИИ)

Этот файл — контекст для продолжения работы в новой сессии/проекте («ETP X» в интерфейсе Claude). Прочитай его целиком перед тем, как что-то менять в коде. Дочерние документы (тоже прочитать целиком до вёрстки): `docs/PROJECT_BRIEF.md` (общий бриф), `docs/TZ_ZAKUPKI.md` (детальное ТЗ на модуль «Закупки» — списки процедур и карточка процедуры намеренно копируют структуру Bidzaar и Битрикс24, см. раздел 0 там).

Пользователь **не разработчик** — для любых шагов, которые требуют от него что-то сделать руками (кликнуть в чужой панели, найти ключ, вставить пароль), давай короткие пронумерованные шаги простым языком, без жаргона и без лишних пояснений.

## Стек

Next.js 16 (App Router) + TypeScript + Tailwind v4 + shadcn/ui (new-york, база — **Base UI**, не Radix) + Prisma 6.19.3 + Postgres (Supabase) + Supabase Auth + pnpm. Хостинг — Vercel. Anthropic API подключён (`lib/ai/`), но `ANTHROPIC_API_KEY` в `.env` пустой — ИИ-помощник отвечает вежливой заглушкой вместо реального ответа, пока ключ не появится (см. ниже).

## Важные технические решения и грабли (не переспрашивать, если не сказано иное)

- **Prisma зафиксирован на 6.19.3**, не 7.x — Prisma 7 убрал `url = env("DATABASE_URL")` из schema.prisma в пользу `prisma.config.ts` + driver adapters.
- **`postinstall: "prisma generate"` в `package.json` — обязателен, не убирать.** Без него Vercel может закэшировать `node_modules` с прошлого деплоя и НЕ перегенерировать Prisma Client под новую схему — тогда сборка падает на TS-ошибке вида `Property 'x' does not exist in type 'YInclude'`, хотя локально всё собирается (там клиент уже свежий после ручного `prisma db push`). Поймали и почин или именно так один раз — если увидишь такую ошибку в логах Vercel, первым делом проверяй этот скрипт на месте.
- **Пул соединений Supabase (порт 6543) иногда подвисает на 1–5 секунд или отдаёт transient-ошибку** `Can't reach database server`. Из-за этого **каждый клиентский вызов server action обязан быть в `try/catch` с `toast.error(...)`**, иначе необработанная ошибка внутри `useTransition` роняет весь экран в красный dev-оверлей Next.js (выглядит как серьёзный краш, а на деле просто нужно было поймать ошибку). Один раз словили именно так в чек-листе — если добавляешь новый клиентский вызов server action, сразу оборачивай.
- Next.js 16: файл `middleware.ts` переименован в **`proxy.ts`**, функция называется `proxy`, не `middleware`.
- shadcn `Button` использует `render` от Base UI, не `asChild` от Radix: `<Button render={<Link href="/x" />}>`. Если `render` рендерит не `<button>` — добавляй `nativeButton={false}`.
- shadcn `Select` (Base UI): `<SelectValue />` без `items` на `<Select>` показывает **сырое значение**, а не подписанный label, и это не чинится последующим выбором. Фикс — `<Select items={{ VALUE: "Подпись" }}>`.
- `components/ui/sidebar.tsx` → `SidebarInset` требует `min-w-0` в class-list, иначе широкий контент (таблицы с горизонтальным скроллом) раздувает `<main>` и скроллится вся страница целиком вместо самого блока. Уже исправлено, не убирать `min-w-0`.
- Дропдауны (`DropdownMenuLabel` и т.д.) обязаны быть внутри `<DropdownMenuGroup>`, иначе краш "MenuGroupContext is missing".
- `Prisma.User.id` = id пользователя Supabase Auth напрямую, без отдельной таблицы-связки.
- **Основной рабочий каталог Claude-сессии может быть привязан не к `etp`, а к соседнему проекту `specification` (repo `specification-anna`)** — это задаётся при создании сессии и не меняется изнутри диалога никаким инструментом. Пользователь явно запретил трогать `specification-anna` вообще, даже нетрекаемыми файлами типа `.claude/launch.json`. Использовать **только абсолютные пути** (`/Users/emilakmaev/Downloads/etp/...`) во всех Read/Write/Edit/Bash. Для превью в браузере — `mcp__Claude_Browser__preview_start({url: "http://localhost:3000"})` напрямую, это не требует `launch.json` и ничего не пишет в другой проект. Если нужен по-настоящему новый чат с сессией, привязанной к `etp` — это делается через **New** в интерфейсе с выбором папки `etp`, не изнутри существующего диалога.
- Браузерное тестирование: `ref_N` из `read_page`/`find` быстро протухает, а клики по «сырым» screenshot-координатам промахиваются (масштаб скриншота не совпадает с реальным вьюпортом — коэффициент плавает от вьюпорта к вьюпорту, не константа). Надёжнее всего — `document.querySelector(...).click()` / прямая установка `.value` через нативный сеттер + `dispatchEvent(new Event('input'))` в `javascript_tool`. `computer{action:"scroll"}` может подвисать — скроллить контейнер напрямую через `element.scrollLeft/scrollTop` в JS.
- **Правило поэтапной работы над крупными фичами** (сложилось на модуле «Закупки», стоит повторять для следующих больших кусков): сначала — построчный разбор ТЗ/референсов с явным вердиктом соответствия по каждому пункту и планом на уровне компонентов, без кода; после согласования — этапы «схема → данные/списки → основной UI → интеграции», с git-коммитом и пушем после каждого этапа, коротким отчётом с живой проверкой в браузере перед переходом к следующему.
- Тестовые аккаунты в базе (email/пароль вспомнить неоткуда, кроме как из истории конкретной сессии, где они создавались): `test.etp.messenger@gmail.com` (компания «ООО Тест Мессенджер», организатор тестовых процедур), `test.etp.participant@gmail.com` (компания «ООО Тест Участник»). Плюс несколько более старых `test.etp.mvp*@gmail.com`. Настоящий аккаунт пользователя — `akmaevtat@gmail.com` (пароль неизвестен агенту, не запрашивать — пользователь логинится сам).

## Окружение

На этой машине изначально не было Node/pnpm в PATH инструмента Bash. Node 24 LTS в `~/.local/node` (без sudo), pnpm через corepack, `gh` CLI в `~/.local/gh/bin`. **Перед любой командой с node/pnpm/prisma/gh** нужно (не сохраняется между вызовами Bash):
```bash
export PATH="$HOME/.local/node/bin:$HOME/.local/gh/bin:$PATH"
```

В базе остались тестовые пользователи/компании/процедуры — можно игнорировать или почистить.

## Git, GitHub, Vercel

- Репозиторий: **github.com/akmaevtat-lang/etp** (публичный). Прод: **https://etp-one.vercel.app**. Автодеплой на пуш в `main` уже подключён.
- **Жёсткое правило: никогда не запускать `git config`**, ни при каких обстоятельствах, даже если пользователь явно просит. Коммиты подписывает сам пользователь через свой Terminal.
- Пуш — через одноразовый URL с токеном, без изменения конфига:
  ```bash
  git push "https://x-access-token:$(gh auth token)@github.com/akmaevtat-lang/etp.git" main
  ```
- После пуша — автодеплой стартует сам, но **не считай задачу завершённой, не проверив `npx vercel ls --yes`** до статуса `Ready` (или разобравшись, если `Error` — читать `npx vercel inspect <url> --logs`). Один раз пуш был зелёным, а прод был сломан несколько коммитов подряд из-за пропущенной перегенерации Prisma Client — см. `postinstall` в разделе выше.
- `pnpm-workspace.yaml` должен содержать `'@prisma/client': true` (не текстовый плейсхолдер) в `allowBuilds`/`onlyBuiltDependencies` — иначе pnpm блокирует postinstall-скрипты и на чистой установке `@prisma/client` не имеет `PrismaClient`.
