# AGENTS.md

Краткие правила работы с репозиторием для следующих сессий Codex.

## Перед изменениями

- Обязательно прочитать `AI_HANDOFF.md`.
- Для задач модуля закупок дополнительно прочитать `docs/TZ_ZAKUPKI.md`.
- `docs/PROJECT_BRIEF.md` использовать как общий продуктовый контекст; более новые явно зафиксированные решения имеют приоритет.
- Текущий код — источник истины о фактической реализации, но он не отменяет автоматически зафиксированные продуктовые требования.
- Если код и требования противоречат друг другу, сначала сообщить владельцу продукта и запросить решение. Не менять бизнес-логику самостоятельно.

## Границы изменений

- Не менять UX-паттерны, архитектуру и бизнес-правила без явного задания.
- Сохранять текущий стек: Next.js + TypeScript + Tailwind CSS + shadcn/Base UI + Prisma + Supabase.
- Не заменять выбранные библиотеки и архитектурные подходы без реальной необходимости и предварительного согласования.
- Не выполнять `push`, destructive git-команды, миграции production-БД и изменения production-конфигурации без явного разрешения.

## Проверка результата

- После крупных изменений запускать доступные typecheck/build-проверки и сообщать точный результат.
- Если проверка не запускалась или была заблокирована окружением, явно указывать это в отчёте.
