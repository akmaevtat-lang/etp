# Электронная торговая площадка с ИИ — проектный бриф

## Идея одной строкой
Современная ЭТП, где организатор проводит закупки/продажи, участники подают предложения,
а ИИ помогает на всех этапах: генерирует ТЗ, разбирает Excel-спецификации, скорит заявки,
пишет протоколы. Цель — быть проще и удобнее классических ЭТП, монетизация через подписку
на доп. услуги (проверка контрагента, лимиты на участие в торгах и т.д.).

## Стек
- **Frontend/Backend**: Next.js (App Router) + TypeScript + Tailwind + shadcn/ui, один репозиторий
- **База данных**: PostgreSQL + Prisma ORM (см. `prisma/schema.prisma`)
- **Auth / Storage / Realtime**: Supabase (RLS удобно ложится на модель "доступ по компании")
- **ИИ**: Anthropic API напрямую (Claude) — генерация ТЗ, парсинг спецификаций, скоринг, протоколы
- **Хостинг**: Vercel + Supabase Cloud
- **Excel**: библиотека `xlsx` (SheetJS) для парсинга загруженных спецификаций

## Модель данных — ключевая идея
В процедурах и предложениях участвует **компания**, а не пользователь напрямую.
Пользователь действует через `CompanyMember` (роль ADMIN/EMPLOYEE) — отсюда бесплатно
получаем "один человек в нескольких компаниях" без дублирования данных.

Полная схема — в `prisma/schema.prisma`.

## Жизненный цикл процедуры
```
Черновик → [Проверка, опционально] → Опубликовано → [Переторжка, опционально]
  → Выбор победителя → Завершено → [Документооборот, опционально]
```
Проверку админом компании в MVP можно пропустить, пока не реализованы роли/приглашения.

## Мессенджер — двухуровневая структура
Треды НЕ принадлежат только процедуре. У треда есть nullable `procedureId`:
- Если задан — тред виден и в общем инбоксе пользователя, и в срезе на странице процедуры.
- Три типа: SYSTEM (уведомления + ИИ-помощник компании), AI (личный чат с ИИ),
  PARTICIPANT (переписка организатор ↔ конкретный участник).

## Онбординг
Регистрация аккаунта → без компании доступен только просмотр площадки (маркетплейс,
открытые процедуры) → создание/присоединение к компании → полный доступ (участие,
создание процедур). Первый пользователь компании автоматически получает роль ADMIN.

## MVP-скоуп

**В работе (реальная логика):**
- Регистрация, создание компании, роль admin
- Процедура: Черновик → Опубликовано → Переторжка → Выбор победителя → Завершено
- Спецификация: фиксированный набор полей + загрузка Excel с ИИ-распознаванием
- Предложения участников (построчно по спецификации)
- Мессенджер: все 3 типа тредов, единый инбокс + срез по процедуре
- ИИ: автогенерация ТЗ/спецификации, скоринг заявок, автопротокол

**Красивые заглушки (UI без логики):**
- Каталог товаров компании / маркетплейс а-ля Авито
- Конструктор доп. полей спецификации
- ЭЦП и юридически значимый документооборот (в MVP — просто загрузка файлов)
- Верификация контрагента, рейтинги, подписки/оплата
- Приглашение сотрудников по email (модель данных уже готова — `invitedBy` в `CompanyMember`)

**Инструмент разработки:** переключатель ролей на странице процедуры (организатор /
участник / гость) — чтобы не гонять несколько логинов при разработке.

## Черновая структура папок
```
/app
  /(marketing)/page.tsx          — публичный маркетплейс, доступен без компании
  /(auth)/login, /register
  /(platform)/onboarding/company — создание/выбор компании
  /(platform)/procedures/new
  /(platform)/procedures/[id]    — вкладки: инфо, спецификация, чат, документы
  /(platform)/inbox              — единый мессенджер пользователя
/prisma/schema.prisma
/lib
  /db.ts                         — Prisma client
  /ai/                           — обёртки над Anthropic API, промпты
/components
  /ui                            — shadcn
  /procedure                     — вкладки, таблица спецификации, чат-виджет
```

## Мессенджер — детализация

**Расположение:** докнутая панель справа, компонент уровня layout (не floating-виджет).
Открыта/закрыта на любой странице через тоггл в шапке, состояние сохраняется между
переходами по разделам.

**Дефолтные чаты компании** (создаются автоматически при создании компании):
- ИИ-помощник — `Thread.type = AI`, `companyId` задан, `procedureId` = null
- Уведомления — `Thread.type = SYSTEM`, `companyId` задан, `procedureId` = null

**Процедурные чаты** (создаются автоматически по ходу процедуры):
- `Thread.type = PARTICIPANT`, `procedureId` задан, `companyId` = участник
- На одну процедуру — по одному треду на каждую компанию-участника
  (организатор виден через `procedure.organizerId`, второй стороной треда
  всегда выступает participant company из `companyId`)

**ИИ-чат — два уровня, строим по порядку:**
1. *Сейчас:* ИИ только предлагает (черновик ТЗ, черновик заявки, подборка
   релевантных процедур) — пользователь сам применяет предложенное.
   Никаких прямых записей в БД от ИИ.
2. *Позже:* агентный режим — ИИ создаёт/редактирует процедуру напрямую,
   но только после явного подтверждения человеком на каждое действие.

**Источник знаний ИИ:** пока не определён. На старте — только контекст
текущей компании (её процедуры, спецификации), без внешней базы знаний.

**Вложения (изображения/документы/опросы):** в MVP — только UI-заглушка
(иконка скрепки, состояние disabled/«скоро»). Поля `attachmentUrl` и
`attachmentType` зарезервированы в модели `Message`, реальной загрузки нет.
